# Learning System

This repository follows a mastery-based progression model.

## Status Values

Each phase uses one of these states:

- `NOT_STARTED`
- `IN_PROGRESS`
- `PASSED`
- `REVIEW_REQUIRED`

## Mastery Gate

A phase is marked `PASSED` only when the learner demonstrates at least 90% mastery through evidence appropriate to the topic.

Evidence can include:

- explanation in the learner's own words
- practical implementation
- debugging
- quiz or test
- code review
- mini project
- architecture explanation
- Git evidence

Reading, watching, copying code, or having old notes is not enough by itself.

## Dependency Rule

The roadmap is followed in dependency order. Advanced AI topics do not replace missing fundamentals.

If a later topic exposes a real prerequisite gap, the gap is repaired deliberately and then the learner returns to the main phase.

## Review Rule

Previously studied material can be used as reference, but old completion claims do not automatically become current mastery.

## GitHub Update Rule

Repository updates should represent real evidence.

Good examples:

- a solved exercise
- a verified note after understanding
- a test result
- a mini project
- a debugging write-up
- a phase checkpoint

Avoid marking progress only because a topic was mentioned or skimmed.

## Mentor Role

The mentor owns:

- roadmap order
- mastery gates
- gap detection
- phase status
- GitHub learning-ledger consistency

The learner owns:

- practice
- answers
- implementation
- asking when something is unclear

## Core Principle

```text
Understand
   ↓
Practice
   ↓
Debug
   ↓
Verify
   ↓
Record evidence
   ↓
PASSED
```
